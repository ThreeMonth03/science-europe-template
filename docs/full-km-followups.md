# 0.3.46 — selected full-KM followups

The previously tested `experiments/full-km-followups` overlay is now in the
shared English source. Chinese is generated by the existing pinned translation
pipeline; there is no independent Chinese Jinja patch or LLM rewriting.

This bounded change restores project file naming (Q3 / SE-2a), reference-data
publication scheduling (Q10 / SE-5a), and reference-data maintenance (Q11 /
SE-5b). These are three verified mappings, not proof of complete KM coverage.
The helper checks compiled KM membership, types, parent edges and selected
ancestors. Inactive or filtered descendants cannot leak. Selected blank text
gets a review-only prompt; submission omits the prompt without inventing facts.

The existing storage file-naming answer remains distinct. Authored Markdown,
case and punctuation are not rewritten. A narrowly scoped CSS rule keeps an
identifier type and value inline; fonts and Word conversion steps are unchanged.

## Regression and version boundary

`requirements/full-km-followups-delta.json` pins every before/after source and
asset hash, metadata, and the immutable prototype commit. The source contract
rejects unknown edits before constructing a test-only 0.3.45 view. Old byte and
hash oracles retain their original scope; actual new branches have separate
positive, missing, inactive, filtered and mutation tests. Historical views are
never distributed as current packages.

Work is on the short-lived `fix/full-km-followups` branch. The prototype branch
and 0.3.45 evidence remain intact. The companion Chinese repository locks the
exact English commit and pairs version 0.3.46. Review/submission are formats of
one source, not long-lived branches. Future upstream merges should use a new
upgrade branch and explicitly reviewed deltas, not relaxed golden hashes.

This integration is not deployment, complete Science Europe coverage, a global
submission switch, or Microsoft Word visual acceptance. Candidate package and
native output evidence are tracked in the Chinese repository.
